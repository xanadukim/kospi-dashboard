# Universe Selection Design — 자동 종목 우주 선정 v1

> 상태: **설계안 (미구현)** — 2026-10 작성
> 목적: 수동 `INDUSTRIES_UNIVERSE`(8업종×8종목=64종)를 KRICS 분류 + 정량 선정 기준 기반의 버전 관리형 우주로 전환한다.

---

## 1. 배경과 문제 정의

현재 우주는 `scripts/daily_update.py`의 `INDUSTRIES_UNIVERSE`에 수동 하드코딩되어 있다.

- 선정 기준이 비공식 — "왜 이 종목인가"에 대한 재현 가능한 답이 없음
- 업종 분류도 수동 매핑 — KRICS 공식 분류 미반영
- DART 부실주 필터는 **스코어링 후** picks에 사후 적용 — 우주 단계에서 부실 종목을 배제하지 않음
- 우주 변경 시 picks/performance 비교 연속성 문제 (본 문서의 핵심 해결 대상)

## 2. 핵심 원칙

### 2.1 측정과 선정의 분리

- **측정 계층** (수익률, 성과): 종목이 우주를 떠나도 실현 수익률 데이터는 유효 — 끊기지 않는다.
- **선정 계층** (무엇을 추천하는가): 우주 버전에 따라 달라진다 — 버전으로 관리한다.
- 백테스트 오염은 "관리 부재"에서 발생한다. 아래 3규칙으로 방지한다.

### 2.2 포인트-인-타임 (Point-in-Time) 원칙 — 최우선

- 선정 입력값은 **스냅샷 날짜 시점에 알 수 있었던 정보**만 사용한다.
- 금지: 미래에 발표될 분류(KRICS 정기변경 결과), 소급 수정되는 재무데이터, 당일 종가 기반 선정.
- 허용: trailing N일/분기 평균 시총·거래대금, 해당 시점 최신 DART 사업보고서, 확정된 KRICS 분류.
- 위반 시 과거 백테스트가 룩어헤드 바이어스로 부풀려진다 — **이 규칙은 협상의 여지가 없다.**

### 2.3 순환성 금지

- 선정 특성은 모델이 측정하려는 팩터 민감도와 **상관되지 않는 중립 지표**로 제한한다.
- 금지 예시: "외국인 수급 민감도", "모멘텀" — 모델 출력/입력과 겹치면 팩터 해석이 순환된다.
- 허용 예시: 시가총액, 거래대금(유동성), 부채비율, 영업이익률, 결산 신뢰도.

## 3. 우주 버전 스키마

### 3.1 Firestore 컬렉션 `universe_membership`

```
universe_membership/{version_id}
  version: "v2"
  effective_date: "2026-12-11"        # 실제 적용일
  created_at: timestamp
  criteria_version: "sel_v1"          # 선정 규칙 버전
  source: "krics_kospi200"            # 데이터 출처
  industries: {
    "elec": ["005930", "000660", ...],
    ...
  }
  meta: {
    universe_size: 96,
    overlap_with_prev: 0.72,
    notes: "KRICS 첫 적용"
  }
```

### 3.2 스냅샷 태깅

- `factor_snapshots/{date}`에 `universe_version` 필드 추가.
- `performance_tracking` 레코드에도 동일 태그 — 어느 우주에서 추천됐는지 추적.
- 프런트 성과 차트에 버전 전환일 수직 경계선 표시, 지표는 버전별 분리 보고.

### 3.3 버전 규칙

- 우주 구성이 바뀌는 모든 변경(정기변경, 기준 개정, 장애 복구)은 **새 version**이다. 기존 문서는 절대 수정하지 않는다.
- 일시적 제외(거래정지 등)는 version 변경이 아니라 `suspended` 플래그로 처리 — 복귀 시 원래 version 유지.

## 4. 선정 파이프라인 (2단계)

### Stage 1 — 부실주 제거 (제외 필터)

목적: 명백한 부실 기업을 우주 진입 전에 차단. **탈락 사유를 기록**한다.

| 기준 | 데이터 소스 | 초기 임계값(안) |
|---|---|---|
| 감사의견 부적정/한정 | DART audit_opinion | 비적정 의견 시 제외 |
| 관리종목/투자경고 | KRX | 지정 시 제외 |
| 연속 결손 | DART 재무 (3개년) | 3개년 연속 영업적자 시 제외 |
| 영업현금흐름 | DART CF | 2개년 연속 영업CF 적자 시 제외 |
| 거래정지/거래희박 | KRX | 20일 평균 거래대금 하위 5% 제외 |
| 상장폐지 위험 | KRX | 관리종목 사유 보유 시 제외 |

- 기존 `fundamental_filter.py`의 완화된 재무 기준(ROE/부채/유동비율)은 **Stage 2 가점 감점**으로 격하 — 사후 picks 필터가 아니라 선정 점수의 입력으로.
- `TICKER_TO_CORP` 하드코딩 매핑(~18종목)을 DART corpCode.xml 전체 파싱으로 교체 — 우주 확대의 선행 과제.

### Stage 2 — 특성 기반 선정 (포함 필터)

목적: 업종별 대표성과 유동성을 갖춘 종목을 정량 선정.

| 특성 | 기준(안) | 비고 |
|---|---|---|
| 시장 대표성 | 업종 내 시가총액 상위 | KRICS 업종별 정렬 |
| 유동성 | 60일 평균 거래대금 상위 50% | 스프레드/체결 안정성 |
| 재무 건전성 | DART 점수 (ROE·부채·영업이익률 종합) | Stage 1 통과분에 한함 |
| 업종당 종목 수 | 업종별 8~12종목 (KRICS 세분류 수에 따라 가변) | 소수 업종은 최소 5종 보장 |

- 업종당 종목 수를 고정하지 않는 이유: KRICS 세분류별 종목 수 편차가 크므로, 최소 수만 보장하고 나머지는 점수 상위로 채운다.

## 5. KRICS 연동 로드맵

| 시기 | 이벤트 | 작업 |
|---|---|---|
| 2026-10-26~30 | KRICS 분류 발표 + 의견수렴 | 분류표 수집, 8개 업종 매핑 테이블 초안 작성 |
| 2026-11 중 | KOSPI200/KOSDAQ150 구성종목 발표 | 우주 후보 풀 확정, Stage 1/2 선정 엔진 개발·검증 |
| 2026-12-11 | 정기변경 + KRICS 적용 | `universe_membership/v2` 생성, 섀도우 운영 시작 |
| 2026-12~2027-01 | 섀도우 기간 (4~8주) | 신구 우주 겹침률·가상 성과 비교, 이상 시 v1 유지 |
| 2027-01 이후 | 정식 전환 | v2를 기본 우주로, 프런트에 버전 표시 |

- KRICS 세분류(24개+) → 우리 8개 업종 매핑 테이블을 `js/data.js`와 `industry_betas.py` 양쪽에 동일하게 유지 — 불일치 시 β 적용 오류.
- KRICS 분류가 변경되는 종목(재분류)은 version 변경 없이 `industry_id`만 갱신하는 `reclassify` 이벤트로 처리 — 과거 picks의 업종 라벨은 당시 값 유지.

## 6. 섀도우 운영 절차

1. `daily_update.py`가 매일 **두 우주를 병렬 계산**: v1(기존 64종, 실제 추천) + v2(신규, `shadow` 플래그).
2. shadow 결과는 `factor_snapshots.shadow_picks`에 별도 저장 — 본 picks와 혼합 금지.
3. 매주 `overlap_rate`(v1 추천 ∩ v2 추천), `shadow_hit_rate`(가상 성과)를 `meta_summaries`에 기록.
4. 전환 판단 기준(안): 겹침률 ≥ 60% AND shadow 표본 ≥ 20거래일 AND 데이터 품질 이상 없음.
5. 전환 실패 시 v1 유지 — shadow 데이터는 분석용으로만 보존.

## 7. 성과 연속성 정책

- `performance_tracking`은 우주 버전과 무관하게 **종목 단위로 계속 기록** — 추천된 종목의 수익률은 우주 이탈 후에도 측정한다.
- 성과 탭/백테스트는 `universe_version`별로 구간을 나눠 표시:
  - 누적 곡선에 버전 전환일 수직선 + 범례 "v1(수동 64종) / v2(KRICS 자동)"
  - "최근 성과" 요약은 기본적으로 최신 version만, 이전 version은 별도 접이식 섹션.
- 백테스트는 **각 버전의 기간 내에서만** 유효 — v1 로직을 v2 기간에 소급 적용한 수치는 표시하지 않는다(룩어헤드).

## 8. 호환성 및 마이그레이션

- `weeklyPicks` 스키마에 `universe_version` 필드 추가 — 프런트는 해당 필드가 없으면 `"v1-legacy"`로 간주.
- `INDUSTRIES_UNIVERSE`는 당분간 fallback으로 유지 — universe_membership 로드 실패 시 v1로 자동 강등(REAL_ONLY 원칙과 동일하게 명시적 상태 표시).
- DART `TICKER_TO_CORP`는 우주 확대 종목분을 점진 추가 — 매핑 없는 종목은 Stage 1 자동 제외(부실 판정 불가 = 보수적 제외).

## 9. 리스크 및 금지사항 정리

| 리스크 | 대응 |
|---|---|
| 룩어헤드 바이어스 | 포인트-인-타임 원칙 (§2.2) — 선정 입력의 기준 시점 강제 |
| 순환 선정 | 중립 특성만 사용 (§2.3) |
| 업종 매핑 오류 | KRICS→8업종 매핑 테이블을 단일 소스로, 버전 관리 |
| 소수 업종 종목 부족 | 최소 5종 보장, 미달 시 해당 업종은 v1 구성 유지 |
| 성과 비교 오염 | 버전별 분리 보고 + 차트 경계선 (§7) |
| DART API 장애 | Stage 1 실패 시 해당 종목 보수적 제외 + `data_status` 명시, v1 fallback |
